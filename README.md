# БитКодер — объясняем равномерное двоичное кодирование

Учебный проект «Объясни задачу». **Тема 8, вариант А:** равномерное двоичное кодирование, алфавит из 4–6 символов.

Сайт берёт алфавит и сообщение, кодирует их двоичным кодом одинаковой длины (или расшифровывает строку из нулей и единиц обратно) и показывает всё **по шагам**: на каждом шаге видно, что мы сейчас смотрим, что делаем, какие значения получились и что изменилось. Внутри разбора есть вопросы, а отдельная страница даёт задачу для самостоятельного решения.

Автор: _впишите имя_ (имя в подвале сайта берётся из `BitCoder.Web/appsettings.json`, поле `Site:Author`).

---

## 1. Что здесь решается

Если в алфавите `n` символов, то на каждый символ нужно `k` бит, где `k` — наименьшее число, при котором `2^k ≥ n`. Каждому символу по порядку выдаётся код — его номер в двоичной записи, дополненный нулями слева до `k` бит.

| Символов в алфавите | Бит на символ `k` | Всего кодов `2^k` | Свободных кодов |
|---|---|---|---|
| 4 | 2 | 4 | 0 |
| 5 | 3 | 8 | 3 |
| 6 | 3 | 8 | 2 |

Пример: алфавит `АБВГД` (5 символов, `k = 3`), коды `А=000, Б=001, В=010, Г=011, Д=100`. Сообщение `ГАДБ` → `011 000 100 001` → `011000100001`.

Расшифровка идёт в обратную сторону: строка режется на группы по `k` бит, каждая группа ищется в таблице. Здесь возникают два особых случая, ради которых сделаны отдельные примеры:

* **Неизвестный код.** В группе из `k` бит записан код, которого нет в таблице (при 5 символах свободны `101`, `110`, `111`).
* **Неполная группа.** Длина строки не делится на `k`, и в конце остаётся «хвост».

## 2. Как запустить

**Что нужно:** .NET SDK и больше ничего. Внешних NuGet-пакетов в проектах нет, при сборке на .NET 10 я интернет не использовал.

| Что | Версия |
|---|---|
| .NET SDK, на котором всё проверено | **10.0.112** (Linux) |
| Платформа в проектах | `net10.0` |
| Язык | C# (`LangVersion 12.0`), включены `Nullable` и `ImplicitUsings` |
| Фреймворк | ASP.NET Core MVC + Razor (`.cshtml`) |
| Внешние NuGet-пакеты | нет |
| JavaScript | нет |

Запуск сайта:

```bash
cd BitCoder.Web
dotnet run
```

Откройте <http://localhost:5080>. Запускайте именно из папки `BitCoder.Web` (или через `dotnet run --project BitCoder.Web` из корня), иначе сервер может не найти папку `wwwroot` со стилями и шрифтами.

Запуск проверок (45 штук):

```bash
dotnet run --project BitCoder.Tests
```

Тесты — обычная консольная программа, а не xUnit: она печатает `OK`/`FAIL` для каждой проверки и итог. xUnit я не использовал, потому что при разработке не было доступа к NuGet. Если хотите xUnit, логика проверок переносится почти один к одному.

**Если у вас .NET 8 SDK:** в `Directory.Build.props` замените `net10.0` на `net8.0`. Версия платформы указана только там. **Это я не проверял:** в среде, где я разрабатывал, восстановить пакеты для .NET 8 не удалось (нет доступа к NuGet), так что работу на .NET 8 гарантировать не могу. Код не использует ничего из .NET 10 сознательно, но «не использует» и «проверено» — разные вещи.

## 3. Архитектура

### 3.1. Общая картина

Проект — **ASP.NET Core MVC** с представлениями **Razor**, без JavaScript. Сервер сам собирает HTML-страницу при каждом запросе. Решение состоит из трёх проектов:

```
BitCoder.sln
├── BitCoder.Core     Вся «математика» и содержание урока. Не знает про веб.
├── BitCoder.Web      Контроллеры, представления Razor, CSS, шрифты. Ссылается на Core.
└── BitCoder.Tests    Проверки Core (консольная программа). Ссылается на Core.
```

```
 Браузер                      BitCoder.Web                              BitCoder.Core
 ───────                      ────────────                              ─────────────
 GET /lesson?a=АБВГД     ──►  LessonController  ── проверка ввода ──►   CodeTable.TryCreate
        &mode=enc             (читает адрес)                            InputRules.TryParse…
        &in=ГАДБ              │
        &step=3               ├── строит урок ────────────────────────► LessonBuilder.Build
                              │                                          └─ Coder.Encode/Decode
                              │                                          └─ список Step с Question
                              │
                              ├── выбирает шаг №3, проверяет ответ ───► Question.Check
                              │
                              └── передаёт LessonViewModel
                                       │
                                       ▼
                                 Views/Lesson/Index.cshtml (Razor)
 HTML + CSS             ◄───────────────┘
```

### 3.2. Что за что отвечает

**BitCoder.Core** — библиотека классов. В ней нет ссылок на ASP.NET, поэтому она проверяется тестами без запуска сервера.

| Файл | Ответственность |
|---|---|
| `CodeTable.cs` | Таблица кодов: проверка алфавита (4–6 различных букв), вычисление `k`, код символа и поиск символа по коду, свободные коды |
| `InputRules.cs` | Правила ввода: убрать пробелы и запятые, проверить, что в сообщении только буквы алфавита, а в строке бит — только `0` и `1`, ограничения длины |
| `Coder.cs` | Само кодирование и расшифровка. Для расшифровки каждая группа получает свой результат, включая ошибки |
| `Piece.cs` | Один «кусочек» разбора: индекс, символ, группа бит, ошибка (`UnknownSymbol`, `UnknownCode`, `IncompleteGroup`) |
| `Step.cs`, `Lesson.cs` | Описание шага (что смотрим, что делаем, значения, что изменилось, какое состояние рисовать) и всего урока |
| `LessonBuilder.cs` | Сборка списка шагов по таблице, режиму и вводу. Здесь же решено, на каких шагах стоят вопросы |
| `Question.cs` | Вопрос и его проверка. Если ответ неверный, возвращается подсказка, но **не** правильный ответ |
| `Presets.cs` | Три готовых примера: вводный (`АБВГ`), основной (`АБВГД`) и два особых случая (неизвестный код, неполная группа) |
| `PracticeTask.cs` | Задачи для самостоятельного решения, проверка ответа и объяснение ошибки |
| `Ru.cs` | Склонения («1 бит, 2 бита, 5 бит»), показатели степени |

**BitCoder.Web** — тонкий слой. Контроллеры принимают запрос, вызывают Core и отдают результат представлению. Расчётов в нём нет.

| Часть | Файлы | Ответственность |
|---|---|---|
| Controller | `HomeController`, `LessonController`, `PracticeController` | Читают параметры адреса, **проверяют ввод**, вызывают Core, собирают модель представления |
| Model | `Models/ViewModels.cs` и др. | Готовые данные для страницы (в том числе адреса кнопок) |
| View | `Views/**/*.cshtml` | Вся разметка. Решений о расчётах в представлениях нет |
| Статика | `wwwroot/css`, `wwwroot/fonts` | Стили, анимации, шрифты |
| Точка входа | `Program.cs` | Подключение MVC и один маршрут `/{controller}/{action}` |

Зависимость идёт в одну сторону: **Web → Core**. Если случайно добавить ссылку из Core в Web, проект перестанет собираться: это проверяет компилятор, а не договорённость.

### 3.3. Где хранится состояние

**Нигде на сервере.** Сервер не помнит между запросами ни сессий, ни пользователей, ни базы данных. Всё состояние урока лежит **в адресе страницы**:

| Параметр | Что значит |
|---|---|
| `a` | алфавит (`АБВГД`) |
| `mode` | `enc` — закодировать, `dec` — расшифровать |
| `in` | сообщение или строка бит |
| `step` | номер текущего шага |
| `ans` | ответ на вопрос шага |

Кнопка «Следующий шаг» — это обычная ссылка, у которой `step` на единицу больше. Форма с данными и форма с ответом — обычные HTML-формы с методом GET. На каждый запрос сервер заново строит весь урок и показывает один шаг.

Почему так: это самый простой способ, при котором состояние нельзя потерять и не нужно синхронизировать. Цена — урок пересчитывается при каждом нажатии. Для 24 символов это мгновенно (см. ограничения).

### 3.4. Путь одного нажатия «Следующий шаг»

1. Браузер переходит по ссылке `/lesson?a=АБВГД&mode=enc&in=ГАДБ&step=4`.
2. `LessonController.Index` получает параметры.
3. Алфавит и ввод проверяются в `CodeTable.TryCreate` и `InputRules`. При ошибке пользователь видит сообщение рядом с формой, разбор не строится.
4. `LessonBuilder.Build` строит все шаги урока.
5. Контроллер берёт шаг №4. Если номер не число или выходит за пределы, он заменяется ближайшим допустимым.
6. Если в шаге есть вопрос и пришёл `ans`, ответ проверяется в `Question.Check`.
7. Контроллер строит адреса кнопок «Сначала», «Назад», «Следующий шаг» и передаёт модель в `Lesson/Index.cshtml`.
8. Razor рисует страницу: клетки с битами, четыре строки пояснения («Смотрим», «Делаем», «Значения», «Что изменилось»), вопрос и кнопки.

### 3.5. Проверка ввода на сервере

Проверка идёт при **каждом** запросе, а не только при отправке формы, потому что адрес можно написать руками. Правила: в алфавите только буквы (регистр и разделители не важны), от 4 до 6 различных символов; сообщение — не длиннее 24 символов и только из букв алфавита; строка бит — не длиннее 96 символов и только из `0` и `1`; режим — только `enc` или `dec`; `step` — число, иначе ближайшее допустимое; `ans` обрезается до разумной длины. Вывод в HTML экранирует Razor, поэтому ввод вида `<script>` показывается как текст.

Ошибки возвращаются **значениями** (`bool` + текст ошибки, `PieceError`), а не исключениями: неверный ввод — обычная ситуация, а не сбой.

### 3.6. Что происходит при смене данных и перезагрузке

* **Обновление страницы (F5)** показывает ровно тот же шаг: всё нужное в адресе. Пока не нажата кнопка проверки, ответ на вопрос не отправлен — это нормально.
* **Смена данных** (форма с алфавитом/сообщением) отправляет запрос **без `step`**, поэтому урок начинается с шага 1, а ответы на вопросы сбрасываются. «Состояние сбрасывается» здесь означает не «мы что-то стираем», а «в новом адресе нет старого шага и старого ответа».
* **Кнопка «Назад» браузера** работает как обычно: каждый шаг — отдельная страница в истории.
* Если в адресе перепутан или испорчен `step` (`abc`, `999`, `-5`), сервер показывает ближайший допустимый шаг, а не ошибку.

### 3.7. Визуализация

Каждый бит — одна клетка на листе в клеточку, как в тетради. Синие чернила — коды, жёлтый маркер — текущий символ или группа, красный — ошибка, зелёный — верно. Анимации (проведение маркером, появление клетки, «удар» по ошибке) сделаны только на CSS, без JavaScript. При включённом в системе `prefers-reduced-motion` анимации отключаются. Шрифты (Onest, Caveat, JetBrains Mono) лежат в проекте, внешние сервисы не нужны.

## 4. Обоснование технологий

**Почему C#.** Язык задан учителем; кроме того, он строго типизирован, как требует задание, и ошибки в именах и типах ловятся при сборке.

**Почему ASP.NET Core, а не .NET Framework / Web Forms.** ASP.NET Core — современная кроссплатформенная платформа: работает на Windows, Linux и macOS, запускается одной командой `dotnet run`, поддерживается сейчас. Web Forms и классический ASP.NET работают только в .NET Framework на Windows и развиваются слабо; для нового проекта выбирать их незачем.

**Почему MVC, а не Razor Pages или Blazor.** Задание просит показать архитектуру и защитить её. В MVC роли разделены явно: контроллер принимает запрос и проверяет ввод, модель несёт данные, представление рисует. Это удобно объяснять и защищать. Razor Pages сделали бы код короче, но разделение было бы менее наглядным. Blazor требует либо постоянного соединения (Server), либо загрузки среды выполнения в браузер (WebAssembly), а для сайта, где вся логика нужна на сервере, это лишнее. Это моё обоснование выбора, а не единственно возможный ответ: Razor Pages тоже подошли бы.

**Почему без JavaScript.** Все требуемые функции (шаги, вопросы, проверка, сброс при смене данных) решаются обычными ссылками и формами. Меньше кода, нечему ломаться, а логика и проверка ввода на сервере — как того и требует задание.

**Почему Core отдельно от Web.** Расчёты можно проверять тестами без сервера; веб-часть остаётся тонкой; зависимость в одну сторону проверяет компилятор.

**Почему без базы данных.** Хранить нечего: ввод пользователя и состояние урока целиком помещаются в адрес.

| 2 | Особый случай | `АБВГД`, расшифровка `000111` | `000` → `А`, затем `111` — неизвестный код | совпало |

| 3 | Неправильный ввод | Алфавит из 2 букв, из 7 букв, с повтором, с цифрой, с эмодзи, пустой; чужая буква в сообщении; пустое сообщение; `2` в строке бит | В каждом случае понятное сообщение об ошибке, разбор не строится | совпало |
| 4 | Смена параметра | Число символов 4, 5, 6, 8, 9; добавление буквы `Д` | `k` = 2, 3, 3, 3, 4; код `Г` удлиняется с 2 до 3 бит | совпало |

Кроме того, я прогнал сайт по HTTP (запросы ко всем шагам шести сценариев и к невалидным адресам): все страницы отвечают без падений, испорченные `step` приводятся к допустимым, `<script>` в алфавите выводится как текст. Это были мои скрипты, в репозиторий они не входят.

## 6. Ограничения и что не проверено

* **Алфавит:** 4–6 различных букв, как в варианте А. Только буквы (кириллица, латиница и т. д.); цифры и знаки не принимаются.
* **Длина:** сообщение до 24 символов, строка бит до 96 бит — чтобы урок помещался на экране и пересчитывался мгновенно.
* **Только равномерный код:** неравномерные коды (Хаффман, Фано) не рассматриваются.
* **Нет учётных записей и сохранения прогресса:** ответ на вопрос не запоминается, пока вы его не отправите.
* **Адрес содержит ввод пользователя:** кому-то отправить ссылку удобно, но данные видны в адресной строке и истории.
* **Тесты:** консольная программа, не xUnit; интерфейс автоматическими тестами не покрыт.
* **Не проверено:** сборка на .NET 8; работа на Windows и macOS (проверялось на Linux); внешний вид и анимации в настоящих браузерах (смотрелось только в headless Chromium на ширинах 1280 и 390 px, горизонтальной прокрутки нет); публикация на хостинге; проверка «одноклассник прошёл без подсказок» (её ещё нужно провести).

## 7. Публикация (для оценки 7)

В проект добавлены `Dockerfile`, `.dockerignore` и `render.yaml` для хостинга [Render](https://render.com) (бесплатный web service). Порт берётся из переменной окружения `PORT`, которую задаёт хостинг (по умолчанию 10000).

Шаги:

1. Загрузите проект в репозиторий на GitHub.
2. В Render: New → Blueprint (или Web Service), выберите репозиторий. Render найдёт `render.yaml` и соберёт образ из `Dockerfile`.
3. Дождитесь окончания сборки и откройте адрес вида `https://bitcoder.onrender.com`.

Что проверено: сборка `dotnet publish` и запуск результата с `ASPNETCORE_ENVIRONMENT=Production` и `PORT=10001` (главная, `/lesson`, `/practice`, стили, шрифты отвечают 200, несуществующая страница даёт 404). Что **не** проверено: сборка самого Docker-образа (в среде разработки не было работающего Docker) и сам деплой на Render.

Ограничения бесплатного тарифа Render: сервис засыпает через 15 минут без запросов, первый запрос после этого занимает около минуты ([документация Render](https://render.com/docs/free)). Откройте сайт за несколько минут до защиты. Сайт хранит всё состояние в адресе, поэтому потеря локальных файлов при перезапуске ему не мешает.
